## Purpose
Document how to operate, monitor, and recover the system during incidents.

## RunPod pod failures

RunPod strategies (`runpod-wan`, `runpod-wan22`, `runpod-wan-enriched`, `runpod-vace`,
`runpod-ltx2`) share pod lifecycle handling in `runpod_pod.RunPodSession`:

- **Pod dies before ComfyUI is ready** (CUDA init failure, no capacity on a GPU type,
  ComfyUI never comes up) — `RunPodSession.with_setup_retry` re-provisions on a fresh
  pod automatically, up to `POD_SETUP_ATTEMPTS` times with linear backoff. Nothing to
  do manually unless every attempt is exhausted; if so, check RunPod capacity for the
  configured GPU types before retrying by hand.
- **GPU/cloud fallback order** — `LOSSY_RUNPOD_CLOUD` controls the cloud fallback order
  (default `COMMUNITY,SECURE`; community is tried first and fully exhausted across all
  configured GPU types before escalating to secure cloud, which costs more but is
  guaranteed). Set `LOSSY_RUNPOD_CLOUD=SECURE` to pin to secure cloud, or reorder to
  change preference.
- **Stray pods left running** — on exit, a session asks RunPod what's still running:
  its own leftovers are terminated automatically; a pod from a different session is
  only reported, not touched. `LOSSY_RUNPOD_SWEEP=1` forces termination of those too —
  use with care, it can kill someone else's active work.
- **First clip after a fresh pod boot fails** even though `/system_stats` returned 200
  — that endpoint proves the server process is up, not that the model is sampleable
  yet. This is retried once automatically at the same seed; if it fails twice in a row
  something is actually wrong with the pod.
- **`--keep-pod` idle cost** — pass a duration (default 30 min); the pod arms its own
  `runpodctl remove pod $RUNPOD_POD_ID` before the local process exits, so an
  unattended gap between pipeline stages doesn't bill an idle GPU indefinitely. Never
  run a RunPod strategy expecting to come back to it much later without this.

## Stitch / join quality knobs

- `LOSSY_CROSSFADE` — seconds of dissolve at chained-part joins in `stitch.py`.
  Defaults to `0` (off) as of 2026-08-02: fixing the I2V conditioning-frame bug
  (chained parts now condition on the true last frame, not ~4 frames early) removed
  the rewind the crossfade was masking, and the dissolve costs a visible doubled edge
  on moving subjects. Set `LOSSY_CROSSFADE=0.24` to re-enable if a future join
  genuinely needs masking.
- Concat always re-encodes rather than stream-copying (fixed 2026-08-02) — retimed
  clips carry per-clip effective frame rates, and stream-copying that mixture produced
  non-monotonic timestamps and black flashes at shot boundaries.

## Resume safety

- A resumed video/audio/speech run is checked against `manifest.encode_fingerprint` of
  the current `shots.json`. If the shot boundaries have changed since the progress file
  was written (e.g. a re-encode renumbered shots), the resume is refused rather than
  silently mixing artifacts from two different encodes. Legacy progress files that
  predate this check are caught by an mtime fallback (a `shots.json` newer than the
  progress file implies the encode moved on). If a resume is unexpectedly refused,
  check whether the output dir's `shots.json` was regenerated by a later encode run —
  archive or delete the stale progress/artifacts rather than bypassing the check.
